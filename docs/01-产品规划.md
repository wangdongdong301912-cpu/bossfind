# BossFind 初版产品规划

## 1. 产品目标

BossFind 是一个本地运行的求职辅助工具。用户配置 Boss 直聘账号、目标城市、岗位关键词、薪资范围、招呼模板和常见问答后，系统完成岗位筛选、匹配评分、消息生成、问答建议和执行审计。

初版的第一原则是“可验证、可撤销、不会偷偷发送”。默认演练模式不登录站点、不发送消息；真实模式必须经过页面适配、验证码人工接管和发送前确认。

## 2. 用户流程

1. 在本地页面建立 30 分钟临时凭据会话。
2. 配置目标城市、岗位范围、薪资和经验要求。
3. 编辑固定招呼模板，可使用岗位变量。
4. 配置到岗时间、经验、薪资等简单问答规则。
5. 生成岗位匹配预览，检查排序和文案。
6. 运行演练并查看每条记录。
7. 完成测试账号联调后，再开放真实登录、岗位搜索和逐条发送。

## 3. MVP 功能范围

- 本地临时凭据会话：密码只存在服务进程内存，不写数据库、不写日志，30 分钟自动过期。
- 投递策略：城市、岗位关键词、行业、薪资、经验、每日上限、随机间隔和工作时段。
- 招呼模板：支持 `{job_title}`、`{company}`、`{experience}`。
- 规则问答：关键词匹配并生成“建议回复”；未命中、隐私、面试和承诺类问题转人工。
- 岗位预览：初版提供明确标注的演示数据，用来验收筛选、评分和文案链路。
- 演练执行：生成招呼但不访问 Boss 直聘，不产生站外副作用。
- 审计记录：记录岗位、匹配度、生成文案、状态、原因和时间。
- 站点适配器：实现状态机和安全边界；验证码只允许人工处理，不做绕过。

## 4. 暂不包含

- 绕过滑块、短信验证、设备验证或反爬策略。
- 在未经确认的情况下批量发送消息或投递简历。
- 把账号密码持久化到 SQLite、浏览器存储或日志。
- 用大模型擅自承诺薪资、入职时间、隐私信息或面试时间。

## 5. 技术架构

```text
浏览器工作台（HTML/CSS/JS）
        │ REST API
FastAPI 本地服务
  ├─ 策略与问答服务
  ├─ 内存凭据保险箱（30 分钟）
  ├─ SQLite 配置/审计库
  └─ BossAdapter
       ├─ 公开页探测
       ├─ 人工验证码接管
       └─ 真实发送确认闸门
```

## 6. 风控策略

- 默认 `dry_run=true`。
- 每日上限默认 20，消息间隔默认随机 45–120 秒。
- 只在配置的工作时段运行。
- 真实动作要求有效临时会话和 `confirm_external_action=true`。
- 检测到验证码、访问异常、账号保护或页面结构变化时立即停止。
- 每条外发消息保留可追溯记录，后续支持逐条人工批准。

## 7. 迭代计划

### P0：本次交付

完成本地工作台、配置、临时凭据、预览、模板、规则问答、演练和审计。

### P1：真实站点联调

使用专用测试账号，在用户人工完成验证码后采集登录后页面结构；实现岗位列表读取、详情去重和逐条发送确认。

### P2：小流量试运行

每天 5–10 条，加入失败熔断、重复岗位去重、黑名单、消息收件箱轮询和人工审批队列。

### P3：生产化

多用户权限、HTTPS、密钥服务、任务队列、监控告警、数据保留策略和平台规则复核。

## 8. 进入真实联调前需要

- 一个专用的 Boss 直聘测试账号（请只在本地页面输入，不要发在聊天里）。
- 一份脱敏简历或候选人画像。
- 目标岗位、城市、薪资、排除行业/公司清单。
- 3–10 条真实常见问题及可接受回答。
- 每日联系上限和允许的工作时间。
- 对平台当前用户协议和账号自动化风险的确认。

## 9. 短信验证码登录实现

- 登录地址：`https://www.zhipin.com/web/user/?intent=0`。
- 流程：手机号暂存 → 用户同意平台协议 → 请求短信 → 用户手动输入 6 位验证码 → 建立内存浏览器会话。
- 默认启动可见 Chromium，滑块或安全验证由用户在浏览器内手动完成。
- 登录浏览器和 Cookie 不写入持久化目录；退出、会话释放或服务关闭时销毁。
- 页面输入框和按钮均进行唯一性检查，页面结构变化时停止而不是猜测操作。
